## 배포 경로 조사 (읽기 전용, 배포 안 함)

- 지금까지의 배포(`deploy/workers-kv/deploy.py`)는 API 토큰(Bearer) 으로 Cloudflare REST API 를 직접 호출합니다. 토큰은 저장소·환경 어디에도 남아 있지 않습니다.
- 이 컴퓨터의 wrangler(4.x) 는 hana.auskorea@gmail.com OAuth 로 로그인돼 있고 권한에 `workers_scripts (write)`·`workers_kv (write)` 가 있어, **토큰 없이** 같은 배포가 가능합니다. 확인한 것: `wrangler kv namespace list` → `kongi-room-site` (id f25337075f0842cf8b0102704d0e4e91), 사이트 파일 153개(15.4 MB, 지금 올라가 있는 152개 + core.js; 미사용 원본 room_*.png 제외) 수집, `wrangler deploy --dry-run` 에서 바인딩 SITE(KV)·SHARE(kongi-room-share)·SITE_VERSION 세 개가 deploy.py 와 같게 잡힘.
- 그래서 `deploy/workers-kv/deploy-wrangler.mjs` 를 추가했습니다(의존성 없음, wrangler 4 는 `npx wrangler@4` 로 실행). KV 에는 지금 v20261107180320·v20261108113419·v20261109071213·v20261111090140 네 버전(각 152 키)과 feedback/ 2, backup/ 5 키가 있고, `--prune` 은 `v+숫자14자리/` 키만 대상으로 합니다. 대표님이 붙여 넣을 한 줄:

  ```bash
  node deploy/workers-kv/deploy-wrangler.mjs
  ```

  처음 한 번만 `npx wrangler login`. `--dry-run` 으로 미리 보기, `--prune` 으로 오래된 버전 정리.
- 토큰이 꼭 필요한 경우(다른 컴퓨터·CI) 대표님 몫 절차: Cloudflare 대시보드 → 오른쪽 위 프로필 → **My Profile → API Tokens → Create Token** → 템플릿 **Edit Cloudflare Workers** 의 *Use template* → Permissions 에 **Account · Workers KV Storage · Edit** 줄 추가 → Account Resources 에서 본인 계정 선택 → *Continue to summary* → *Create Token* → 화면에 한 번만 보이는 값을 복사 → 터미널에서 `export CLOUDFLARE_API_TOKEN=붙여넣기` 와 `export CLOUDFLARE_ACCOUNT_ID=e7ab36f62d8b207386857fd4b61328fe` 입력(파일에 적지 않음) → `python3 deploy/workers-kv/deploy.py <사이트 파일만 모은 폴더>`.

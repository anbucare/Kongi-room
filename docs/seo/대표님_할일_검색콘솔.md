등록할 주소: `https://kongi-room.anbu-pilot.workers.dev/`
걸리는 시간: 10분 안팎. 돈 들지 않음. 구글 계정(Gmail)만 있으면 됩니다.
이 문서의 순서대로 하면 되고, 에이전트는 이 작업을 대신하지 않습니다(계정 로그인·제출은 대표님 몫).

> 미리 알아둘 것: 등록 뒤 구글이 실제로 페이지를 가져가는 데 며칠~몇 주가 걸릴 수 있습니다. 등록은 "문을 여는 일"이지 순위나 방문을 약속하지 않습니다.

## 0. 준비

1. 아래 수정(이 브랜치)이 main 에 합쳐진 뒤, 터미널에서 저장소 루트로 가서 한 줄 실행해 사이트를 올립니다(이미 로그인돼 있음):
   ```bash
   node deploy/workers-kv/deploy-wrangler.mjs
   ```
   보일 것: 올리는 파일 수와 새 버전 번호, 끝에 "Deployed" 비슷한 줄. 끝 신호: 브라우저에서 `https://kongi-room.anbu-pilot.workers.dev/robots.txt` 를 열면 `User-agent: GPTBot` 줄이 보입니다(새 robots).
2. 브라우저에서 구글 계정(Gmail)에 로그인해 둡니다.

## 1. 속성 만들기 (URL 접두어 방식)

1. 주소창에 칠 글자: `https://search.google.com/search-console/welcome`
2. 보일 것: 왼쪽 "도메인", 오른쪽 "URL 접두어" 두 칸. **오른쪽 "URL 접두어"** 칸에 다음을 그대로 붙여 넣습니다.
   ```
   https://kongi-room.anbu-pilot.workers.dev/
   ```
   (왼쪽 "도메인" 방식은 DNS 설정이 필요해 workers.dev 공유 주소에서는 쓸 수 없습니다.)
3. "계속" 클릭.
4. 보일 것: "소유권 확인" 창. 여러 방법이 접혀 있습니다.

## 2. 소유권 확인 — **"HTML 태그" 방법을 쓰세요**

왜 HTML 태그인가: 배포 스크립트는 정해진 파일(`index.html`, `app.js` 등)만 올리기 때문에, 구글이 주는 `googleXXXX.html` 파일을 루트에 넣어도 **지금 스크립트로는 올라가지 않습니다**. HTML 태그는 `index.html` 안에 한 줄 넣는 것이라 그대로 올라갑니다.

1. 소유권 확인 창에서 **"HTML 태그"** 를 펼칩니다.
2. 보일 것: `<meta name="google-site-verification" content="……" />` 한 줄. 오른쪽 "복사" 를 누릅니다. (content 안의 값은 비밀이 아니지만, 이 문서나 대화에 적지는 마세요.)
3. 그 줄을 에이전트에게 붙여 주거나, 직접 `index.html` 의 `<meta name="robots" …>` 줄 바로 아래에 넣습니다. 들어갈 자리(이미 있는 줄 기준):
   ```html
   <meta name="robots" content="index, follow, max-image-preview:large">
   <meta name="google-site-verification" content="여기에_구글이_준_값">
   ```
4. main 에 합치고 0-1 의 한 줄로 다시 올립니다.
5. 브라우저에서 `https://kongi-room.anbu-pilot.workers.dev/` 를 열고 아무 데나 오른쪽 클릭 → "페이지 소스 보기" → `google-site-verification` 이 보이면 준비 끝.
6. Search Console 창으로 돌아가 **"확인"** 클릭. 끝 신호: "소유권이 확인되었습니다" 초록 화면 → "속성으로 이동".

### (대안) HTML 파일 방법을 꼭 쓰고 싶을 때

구글이 준 `google….html` 파일을 저장소 루트에 넣고, `deploy/workers-kv/deploy-wrangler.mjs` 의 `SITE_FILES` 목록에 그 파일 이름을 한 줄 추가한 뒤 배포해야 합니다(스크립트 수정은 이 작업 범위 밖이라 하지 않았습니다). 올린 뒤 `https://kongi-room.anbu-pilot.workers.dev/google….html` 을 열어 `google-site-verification: google….html` 글자가 보이면 Search Console 에서 "확인".

## 3. 사이트맵 제출

1. 왼쪽 메뉴 "색인 생성" 아래 **"Sitemaps"** 클릭.
2. "새 사이트맵 추가" 칸에 칠 글자: `sitemap.xml` (앞의 주소는 이미 채워져 있음)
3. "제출" 클릭. 끝 신호: 아래 표에 `sitemap.xml` 이 생기고 상태가 "성공" (처음엔 "가져올 수 없음"이 잠깐 보일 수 있음 → 몇 시간 뒤 새로고침).
4. 발견된 URL 수는 1 이 정상입니다(페이지가 하나).

## 4. URL 검사 → 색인 요청 (첫 한 번)

1. 맨 위 검색창(돋보기)에 칠 글자: `https://kongi-room.anbu-pilot.workers.dev/` → Enter.
2. 보일 것: "URL이 Google에 등록되어 있지 않습니다"(처음엔 정상).
3. 오른쪽 **"실제 URL 테스트"** 클릭 → 1~2분 뒤 "URL을 Google에 등록할 수 있음" 이면 정상. "테스트한 페이지 보기"에서 스크린샷에 콩이 방이 보이면 자바스크립트도 잘 돌아간 것.
4. **"색인 생성 요청"** 클릭. 끝 신호: "색인 생성 요청됨" 팝업. 하루에 몇 번만 할 수 있으니 한 번이면 됩니다.

## 5. 등록 뒤 가끔 볼 곳 (주 1회면 충분)

- "페이지"(색인 생성 → 페이지): `https://kongi-room.anbu-pilot.workers.dev/` 가 "색인 생성됨"으로 바뀌면 됨. `/r?…` 주소가 "noindex 태그로 제외됨"에 보이는 것은 **의도한 것**(친구에게 보내는 결과 링크는 검색에 안 나오게 해 둠).
- "실적": 어떤 검색어로 노출·클릭됐는지. 숫자는 여기 것만 믿으면 됩니다.
- "개선사항 → Core Web Vitals": 방문이 적으면 "데이터 부족"이 정상.
- 메일로 "새 소유자", "보안 문제" 알림이 오면 에이전트에게 보여 주세요.

## 6. 대표님 결정 항목 (실행하지 않음)

- **자체 도메인**: `workers.dev` 공유 도메인보다 자체 도메인(예: kongi.anbu.care 같은 하위 도메인은 이미 있는 anbu.care 에 레코드만 추가, 추가 비용 없음)이 검색·공유·기억에 유리합니다. 바꾸면 canonical·og:url·sitemap·robots 의 주소와 Search Console 속성을 새로 만들어야 합니다(옛 주소 301 포함). 결정만 주시면 작업으로 넘깁니다.
- **네이버 서치어드바이저**(https://searchadvisor.naver.com) 등록: 한국어 서비스라 네이버 검색 노출도 의미가 있지만, 현재 전략 문서에서 한국/네이버 채널은 금지 항목이라 **등록하지 않았습니다**. 하려면 구글과 같은 방식(HTML 태그 → 사이트맵 제출)입니다.
- **Bing 웹마스터 도구**: Search Console 을 만든 뒤 "Search Console 에서 가져오기"로 1분이면 되지만, 외부 서비스 제출이라 대표님이 직접 누르셔야 합니다.
